# 도로명주소 → 행정동 판정 : 실행 가능성 검토

작성: 2026-07-30 · 상태: **✅ 실행 가능 (실측 검증 완료)** · 관련 TODO: C-6 / C-9 / A-9

> **결론 먼저**: 가능하다. 그리고 **`JUSO_KEY` 승인을 기다릴 필요가 없다.**
> 이미 보유·검증된 `SGIS` 키로 오늘 착수할 수 있다. A-9(JUSO 신청)는 **폴백으로 격하**한다.

---

## 1. 왜 필요한가

좌표가 없는 데이터가 셋이다. 이들은 주소만 주기 때문에 행정동 단위 집계를 할 수 없다.

| 데이터 | 가진 것 | 필요한 것 | 영향받는 점수 축 |
|---|---|---|---|
| **NEIS 학원교습소** | 주소(도로명), 정원 | 행정동 | `comp_academy` **0.30** |
| **아파트 실거래가** | 법정동+지번, 단지명 | 행정동 | `power_price` 0.12 |
| **K-APT 단지** | 주소, 세대수 | 행정동 | `power_hh` 0.08 |

좌표를 가진 데이터(학교 15021148, 인허가 학원)는 **PIP만으로 해결되므로 이 문제와 무관**하다.

**⚠️ 법정동 → 행정동 매핑표로는 풀 수 없다.** 두 체계가 N:M이라 원리적으로 부정확하다
(`bjd2adm_draft` 53%에서 멈춘 이유. 2026-07-29 폐기 결정).
**주소 단위로 직접 판정**하는 것만이 정답이다.

## 2. 채택안 — SGIS 지오코딩 + 좌표 PIP (2단 경로)

```
도로명주소 문자열
   │
   ├─[경로B · 정본]─→ SGIS geocode.json ─→ x,y (EPSG:5179 UTM-K)
   │                                          ↓ CrsConverter
   │                                       WGS84 경위도
   │                                          ↓ match_adm (PIP)
   │                                    data/geo/adm_<sgg>.geojson
   │                                          ↓
   │                                    ✅ 행정동코드(행안부 8자리)
   │
   └─[경로A · 교차검증]─→ 응답의 adm_cd (통계청 8자리)
                              ↓ code_bridge.json (kostat8_to_mois10)
                          행안부 10자리 → 앞 8자리
                              ↓
                          경로B 결과와 대조 → 불일치 건만 사람이 확인
```

**필요한 부품이 전부 이미 있다.**

| 부품 | 위치 | 상태 |
|---|---|---|
| SGIS 인증키 | `.env` `SGIS_CONSUMER_KEY/SECRET` | ✅ 발급·검증 완료 (2026-07-29) |
| EPSG:5179 → WGS84 변환 | `scripts/collect_poi.py` `CrsConverter` | ✅ 구현됨 (`CRS_DEFS["EPSG:5179"]`) |
| Point-in-Polygon | `scripts/collect_poi.py` `match_adm` / `_pip` | ✅ 구현됨 |
| 행정동 경계 | `data/geo/adm_*.geojson` 256개 | ✅ 전국, 2026-07-01 개편 반영 |
| 통계청8 ↔ 행안부10 브리지 | `data/processed/code_bridge.json` | ✅ 3,558행 1:1 |

**신규 개발은 "지오코딩 호출 + 캐시 + 배치 러너" 한 겹뿐이다.**

## 3. 실측 결과 (2026-07-30)

### 3-1. 경로B 정확도 — 6/6 성공

SGIS 좌표 → WGS84 → PIP 결과가 SGIS가 알려준 행정동명과 **전부 일치**했다.

| 입력 주소 | PIP 판정 | 우리 인구 데이터 |
|---|---|---|
| 서울 강남구 테헤란로 152 | `11680640` 역삼1동 | ✅ 34,228명 |
| 서울 종로구 창신길 1 | `11110680` 창신2동 | ✅ 7,078명 |
| 제주 제주시 문연로 6 | `50110650` 연동 | ✅ 42,905명 |
| **광주 서구 내방로 111** | `12240745` 치평동 | ✅ 28,774명 |
| **전남 무안군 삼향읍 오룡길 1** | `12810256` 삼향읍 | ✅ 37,280명 |
| 서울 송파구 올림픽로 300 | `11710710` 잠실6동 | ✅ 16,060명 |

**전남광주통합 지역 2건이 정상 판정된 것이 핵심이다** — C-9(코드 체계 검증)의 최대 우려가 해소됐다.

### 3-2. 주소 형태별 성공률 — 15/16 (94%)

| 성공 | 형태 |
|---|---|
| ✅ | 도로명 기본 / 건물명 붙음 / **층·호 붙음** / 시도 생략 / **지번주소** / 지번+상세 |
| ✅ | 아파트 단지명 / 아파트 지번 / 리 단위 지번 / **우편번호 앞에 붙음** / **괄호 법정동 병기** |
| ✅ | **구 표기(광주광역시 …)와 신 표기(전남광주통합특별시 …) 둘 다** |
| ❌ | 존재하지 않는 도로명 번호 1건 → **지번 주소로는 성공** |

층·호·우편번호·괄호가 붙어도 그대로 통과했다. 정제(clean)는 안전망이지 필수가 아니다.
실패한 1건은 도로명 번호 자체가 주소DB에 없는 경우이며, **지번 폴백이 유효**하다.

### 3-3. 처리량 — 전국 1회 배치가 30분 내

`requests.Session` 재사용이 결정적이다(TLS 핸드셰이크 절감).

| 방식 | 처리량 |
|---|---|
| 세션 없이 매번 새 연결 | 1.4건/초 ← **이렇게 만들면 19시간** |
| 세션 재사용 · 순차 | 42건/초 |
| **세션 재사용 · 8스레드** | **88건/초** |

연속 40회 호출에서 스로틀·한도 오류 **0건**.

| 대상 | 추정 건수 | 8스레드 소요 |
|---|---|---|
| 아파트 단지 | ~2만 | 약 4분 |
| NEIS 학원·교습소 | ~8만 | 약 15분 |
| **합계** | **~10만** | **약 20분** |

> 변환 대상은 **거래건이 아니라 단지·시설 단위(유니크)** 다. 실거래 수십만 건을 다 돌리는 게 아니다.
> 1회 배치 + 캐시로 충분하고, 이후는 신규 단지·신규 학원만 증분 처리한다.

## 4. 함정 (반드시 지킬 것)

### 4-1. 🔴 경로A(`adm_cd`)를 단독으로 쓰지 말 것

SGIS 응답은 **코드 체계가 섞여 있다.**

```json
{ "sido_nm": "전남광주통합특별시",  ← 신 (2026-07-01 반영)
  "sido_cd": "12",                  ← 신
  "adm_cd": "24020660",             ← 구! (통계청 구 광주 = 24)
  "adm_nm": "치평동" }
```

`sido_cd`는 신코드인데 `adm_cd` 앞자리는 구 통계청코드(광주 24 / 전남 36)다.
그래서 `code_bridge.json` 조회가 **전남광주통합 지역에서만 실패**한다(실측 2/2 실패).

- 서울·제주 등 개편 없는 지역: 브리지 조회 성공, `population.json` 과 정상 조인
- 전남광주통합 393개 동: 브리지에 없음 → **경로B(좌표 PIP)로만 판정 가능**

**→ 판정은 경로B가 정본. 경로A는 교차검증용으로만 쓴다.**

### 4-2. 🟠 `adm_cd`는 통계청 체계라 우리 코드와 다르다

같은 역삼1동인데 체계가 다르다. 절대 그대로 조인하지 말 것.

```
SGIS(통계청8)  11230640
행안부10       1168064000  → 앞8 = 11680640  ← 우리가 쓰는 코드
```

변환은 `code_bridge.json` 의 `kostat8_to_mois10` (3,558건 1:1).

### 4-3. 🟠 세션 재사용을 빠뜨리면 30배 느려진다

3-3 표 참조. 매 호출 새 커넥션이면 19시간, 세션 재사용 8스레드면 20분이다.

### 4-4. 🟡 지오코딩 실패분은 조용히 버리지 말 것

실패는 반드시 카운트해서 보고한다. 학원이 누락되면 `comp_academy` 가
**"경쟁이 없는 좋은 동"으로 잘못 계산된다** — 상담 자리에서 가장 위험한 방향의 오류다.
`no_academy` 플래그와 구분되게 `geocode_failed` 를 따로 남긴다.

### 4-5. 🟡 SGIS 경계는 쓰지 말 것 (기존 결정 유지)

**지오코딩만 쓴다.** SGIS 경계 데이터는 2025년 기준이라 전남광주통합이 미반영이다
(2026-07-29 판정). 경계는 계속 `admdongkor` 스냅샷을 쓴다.

### 4-6. 🔴 "성공"한 지오코딩이 다른 건물일 수 있다 (2026-09-17)

주소 후보를 깎아 가며 재시도하면(경쟁사 축 `addr_norm.candidates()`), **번호가 빠진 후보**가 맞았을 때
좌표는 나오지만 옆 건물이나 동 대표점이다. 실패로 세지 않으니 4-4 의 실패 카운트에도 안 잡힌다.

| 지점 | 적중 후보 | 결과 |
|---|---|---|
| 와이즈만 인천검단 `원당동1030-5` | `원당동 1030` (부번 제거) | 옆 건물 · ~120m · 동 동일 |
| 와이즈만 울산중구 `반구동 (번영로 536 3동)` | `반구동 …` (괄호 제거로 도로명 소실) | 동 대표점 · ~1km · **행정동 오배정**(반구1동 ↔ 반구2동) |

- SGIS 는 신규 개발지의 부번을 모를 수 있다(`원당동 1030-5` 실패, `1030` 성공). JUSO 에는 있다 —
  단 인천 서구 분구 지역은 **`검단구`로 물어야** 나온다(`서구`로는 0건).
- 방어: `addr_norm.lost_number(raw, used)` — 원본의 도로명 번호·지번이 적중 후보에 **하나도** 없으면 유실.
  `build_competitor.py` 하드가드 ⑤ + `verify_c8.py` 가 막는다. 도로명·지번이 둘 다 적힌 주소는 한쪽만 남아도 통과.
- 학원(`collect_neis`)·아파트(`collect_rtms`·`build_kapt`)는 도로명 실패 시 **지번 전체**로만 폴백하고 번호를 깎지 않으며,
  학교는 원천 좌표를 쓴다 → 현재는 경쟁사 축만 해당. ⚠️ 새 파이프라인에 **깎는 폴백**을 넣으면 이 검사도 같이 붙일 것.

### 5-1. ⚠️ JUSO 폴백을 실제로 쓸 때 (2026-08-04 실측)

**`admCd` 를 행정동코드로 쓰면 안 된다. 그건 법정동코드다.**

```
GET https://business.juso.go.kr/addrlink/addrLinkApi.do
    ?confmKey=<JUSO_KEY>&keyword=서울특별시 강남구 테헤란로 152
    &resultType=json&addInfoYn=Y          ← addInfoYn 없으면 행정동 정보가 아예 안 온다

  admCd  = 1168010100   ← 법정동 역삼동   🚫 이걸 8자리로 자르지 말 것
  hemdNm = 서울특별시 강남구 역삼1동      ← 행정동은 **이름만** 온다 (코드 없음)
  → code_map 매칭 = 11680510
```

두 코드가 **형식이 같아서**(10자리 숫자) 잘못 조인해도 에러가 안 난다. 틀린 동에 값이
얹힌 채로 지나간다 — `bjd2adm_draft`(53%) 를 금지한 것과 같은 이유다.

**이름 매칭 시 정규화 2종** (안 하면 절반이 날아간다):

| 차이 | JUSO | code_map | 처리 |
|---|---|---|---|
| 제N동 | `용호제2동` · `개봉제1동` | `용호2동` · `개봉1동` | 숫자 앞 `제` 제거 |
| 시군구 띄어쓰기 | `고양시 덕양구` · `청주시 흥덕구` | `고양시덕양구` · `청주시흥덕구` | 공백 제거 |

실측(K-apt 도로명주소 무작위 표본): **무보정 8/15 → 정규화 후 30/30.**

**✅ JUSO 는 전남광주통합(2026-07-01)이 반영돼 있다.** `광주광역시 서구 상무대로 760` 을
넣으면 `전남광주통합특별시 서구…` 로 돌려준다. SGIS 경계 제공분이 2025년 기준이라
미반영인 것과 대비되므로, **호남권에서는 JUSO 가 오히려 최신**이다.


## 7. 검증 재현 방법

이 문서의 실측은 스크래치패드에서 수행했다. 재현 스크립트를 정식 편입할 때는
`scripts/geocode_addr.py --selftest` 로 3-1 표본 6건을 검사하게 만들 것.

인구 교차 검증은 이미 정식 편입됐다 → `scripts/verify_population.py`

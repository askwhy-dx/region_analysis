# RTMS 아파트 실거래가 자동 수집 규격

작성: 2026-07-30 · 상태: **✅ 실동작 검증 완료** · 관련 TODO: **E-1** (구 C-4 대체)

> **결론**: 국토부 실거래가 공개시스템(rt.molit.go.kr)에서 **인증키 없이** 매매·전월세
> 전국 실거래를 **월 단위 CSV로 자동 다운로드할 수 있다.**
> `DATA_GO_KR_KEY` 대기 없이 구매력 축(`power_price` 0.12 + `power_hh` 0.08)을 실데이터화한다.

---

## 1. 왜 이 경로인가

| 경로 | 상태 |
|---|---|
| **RTMS 공개시스템 CSV** | ✅ **채택.** 키 불필요, 전국 일괄, 개별 거래 단위 |
| data.go.kr 실거래가 OpenAPI | 🔴 `DATA_GO_KR_KEY` 대기 + 시군구×월 루프라 호출량이 크다 |
| R-ONE API | ❌ 집계 통계만. 개별 거래 없음, 읍면동 없음 |

RTMS 는 **거래 단위 미시데이터**이고 `도로명` 컬럼이 있어, [`ADDR_TO_ADM.md`](ADDR_TO_ADM.md)
지오코딩 경로에 그대로 물려 **행정동 집계**까지 갈 수 있다.

---

## 2. 요청 규격 (실동작 확인)

### 2-1. 3단 흐름

```
① GET  https://rt.molit.go.kr/pt/xls/xls.do
        → 세션 쿠키(WMONID, JSESSIONID) + form action 경로 획득
        ⚠️ action 에 ;jsessionid=... 가 박혀 있다. 하드코딩 금지 — 매번 페이지에서 추출

② POST {action of ptXlsDownDataCheck.do}   (건수 사전 확인, 선택)
        → {"cnt":46296}

③ POST {action of ptXlsCSVDown.do}          (본 다운로드)
        → CSV 본문 (인코딩 EUC-KR)
```

action 추출 정규식:

```python
h = session.get(PAGE).content.decode("euc-kr", "replace")
act_csv = re.search(r'action\s*=\s*"(/pt/xls/ptXlsCSVDown\.do[^"]*)"', h).group(1)
```

### 2-2. POST 폼 파라미터

```
srhThingNo      A            물건종류. A=아파트
srhDelngSecd    1 | 2        1=매매, 2=전월세
srhAddrGbn      1            1=지번주소
srhLfstsSecd    1
srhFromDt       2026-06-01   계약일 시작
srhToDt         2026-06-30   계약일 종료
srhSidoCd       ''           빈값 = 전국
srhSggCd        ''

sidoNm/sggNm/emdNm/areaNm/hsmpNm   '전체'

```

### 2-3. 실측 응답 (2026-06 전국)

| 구분 | 본문 크기 | 행수 | 파일명 |
|---|---|---|---|
| 매매 | 8,836,075 B | 46,312 | `아파트(매매)_실거래가_<타임스탬프>.csv` |
| 전월세 | 14,373,904 B | 75,307 | `아파트(전월세)_실거래가_<타임스탬프>.csv` |

### 2-4. 파일 레이아웃

- 상단 **15행이 안내문 + 검색조건 블록**. 컬럼 헤더는 **16행째**(0-based 15).
  → `NO` 또는 `시군구` 가 있는 행을 찾아 헤더로 삼을 것. 행 번호 하드코딩 금지.
- 인코딩 **EUC-KR**.

```
매매    NO 시군구 번지 본번 부번 단지명 전용면적(㎡) 계약년월 계약일 거래금액(만원)
        동 층 매수자 매도자 건축년도 도로명 해제사유발생일 거래유형 중개사소재지 등기일자

전월세  NO 시군구 번지 본번 부번 단지명 전월세구분 전용면적(㎡) 계약년월 계약일
        보증금(만원) 월세금(만원) 층 건축년도 도로명 계약기간 계약구분
        갱신요구권 사용 종전계약 보증금(만원) 종전계약 월세(만원) 주택유형
```

- `시군구` 는 **"시도 시군구 법정동"이 한 문자열**로 들어온다 (`대구광역시 달서구 대곡동`).
- `도로명` 은 도로명+건물번호만 (`상화로 86`). **전체 도로명주소 = 시도+시군구 + 도로명**.

## 3. 함정

### 3-1. 🔴 행정구역 표기는 "다운로드 시점" 기준이다

**계약월 기준이 아니다.** 같은 202605분을 다시 받으면 표기가 바뀐다.

| 대상 | 시도 종수 | 호남권 표기 |
|---|---|---|
| 2026-07-01 이전에 받아둔 202605 파일 | **17종** | 전라남도 1,224 + 광주광역시 1,343 |
| 2026-07-30 재수집한 202604 / 202605 / 202607 | **16종** | 전남광주통합특별시 |

**대응**
1. **전량 재수집하면 표기가 통일된다.** 개편 이전에 받아둔 파일과 섞지 말 것.
2. 그래도 파서는 **시도 종수(16 vs 17)로 표기 세대를 자동 판별해 로그를 남기고**,
   `code_legacy_map.json` 을 통과시켜야 한다. **명칭 조인 금지.**
3. 개편 직후에는 같은 달을 재수집하면 값이 바뀔 수 있으니, `meta` 에 **수집일자**를 반드시 남긴다.

### 3-2. 🔴 같은 달을 다시 받으면 건수가 늘어난다

실거래 신고는 계약 후 계속 들어온다. 202605 매매가 49,724 → **50,938** 로 늘었다(+1,214).

- 최근 2~3개월은 **미확정**으로 보고, 재수집 대상으로 둔다.
- 진행 중인 달은 반쪽이다 (202607 = 31,207건).
- `meta.collected_at` 과 건수를 남겨 재수집 시 증감을 로그로 드러낼 것.

### 3-3. 🟠 일일 다운로드 100회 제한

서버측 검사(`/pt/xls/ptXlsDownCheck.do`)에 `cnt > 100` 이면 차단된다.
매매 12 + 전월세 12 = **24회**라 여유가 있으나, 재시도 루프를 무제한으로 돌리지 말 것.

### 3-4. 🟠 xlsx 경로(`ptXlsExcelDown.do`)는 쓰지 말 것

`ptXlsExcelDown.do` 로 받은 파일은 구조가 달라 `openpyxl` 파싱이 깨졌다(헤더행 탐색 실패).
**CSV 경로(`ptXlsCSVDown.do`)가 깔끔하다.**

### 3-6. 🔴 손상된 본문이 "정상 크기"로 내려온다 (2026-07-31 실측 사고)

24개월 일괄 수집 중 **`sale_202503` 만 10.6MB 중 92%(9,861,576 B)가 NUL 바이트**로 내려왔다.

- HTTP 200 · 파일 크기 정상(다른 달과 비슷한 10MB대) → **크기만 보면 성공으로 보인다**
- CSV 파서는 죽지 않고 **4,124행만 읽고 조용히 끝난다** (정상 재수집분은 54,459행)
- 그대로 두면 그 달이 통째로 빠진 채 평당가가 계산된다. **에러가 아니라 침묵으로 틀린다.**

**대응 — `collect_rtms.py` 에 구현됨**

```
check_body(body)      NUL 바이트 0 · 100KB 이상 · HTML 아님 · 헤더에 '시군구' 존재
                      → 다운로드 직후 검사, 실패 시 세션 재획득 후 1회 재시도, 그래도 실패면 저장하지 않는다
--verify-only         캐시된 원본 전수 재검사 (손상분은 다음 실행 때 자동 재수집)
```

> 재수집분은 바이트 수가 손상분과 **똑같았다**(10,675,572 B). 크기 비교로는 못 걸러낸다 —
> **NUL 검사가 유일하게 유효한 판별**이었다.

### 3-7. 🟠 따옴표가 닫히지 않은 행이 있다

기본 `csv.field_size_limit`(128KB)을 넘겨 `_csv.Error: field larger than field limit` 로 죽는다.
`csv.field_size_limit(2**31-1)` 로 올려 파일 전체가 죽는 것을 막는다.

### 3-5. 🟡 도로명 결측이 있다

| 파일 | 결측 |
|---|---|
| 매매 202605 | 130건 (0.26%) |
| 전월세 202606 | 809건 (1.1%) |

→ 지오코딩 시 **지번 주소(`시군구` + `번지`) 폴백**을 쓴다. 결측을 조용히 버리지 말고 카운트할 것.

## 4. 얻는 것

| 지표 | 컬럼 | 점수 축 |
|---|---|---|
| 평당가·평균 매매가 | `거래금액(만원)` / `전용면적(㎡)` | `power_price` **0.12** |
| 세대수 대리지표 | 단지 단위 집계 | `power_hh` **0.08** (K-APT 보강 전까지) |
| 신축 비중 | `건축년도` | `new_ratio` |
| **전세가율** | 전세 `보증금` ÷ 매매 `거래금액` (단지·면적 매칭) | **E-2 신설 검토** |
| 갱신 인상률 | `종전계약 보증금` vs `보증금` | 보조 |

실측 평균 (2026-05/06 전국): 매매 58,167만원 · 전세 보증금 37,738만원 · 월세 74.9만원

> ⚠️ **전세가율은 기준월을 맞춰야 한다.** 매매와 전월세를 서로 다른 달로 계산하면 안 된다.
> 12개월 동일 구간으로 수집할 것.

## 5. 구현 메모 (E-1)

```
scripts/collect_rtms.py
  --from 202507 --to 202606        기간 (기본: 최근 12개월)
  --kind sale,rent                 매매/전월세
  --no-download                    캐시된 원본만 파싱
  --raw data/raw/apartment/        원본 CSV 캐시

  1. 페이지 GET → 세션 + action 추출 (jsessionid 하드코딩 금지)
  2. 월 × 구분 루프 → CSV 저장  (data/raw/apartment/rtms_<kind>_<YYYYMM>.csv)
  3. 파싱: 헤더행 탐색 · EUC-KR · 시도 종수로 표기세대 판별
  4. code_legacy_map.json 으로 신코드 변환 (명칭 조인 금지)
  5. 단지 유니크 추출 → geocode_addr.py (C-6) 로 행정동 부여
  6. apartment.json / apartment_sgg.json / apartment_sido.json 산출
     meta 에 collected_at · 월별 건수 · 표기세대 · 도로명결측 · 지오코딩실패 기록
```

단지 유니크는 월 1.6~1.7만 건이며 12개월 합쳐도 3~4만 수준이라, 지오코딩은 8스레드로 몇 분이다.

**검증 경로**: 만든 시군구 평균가를 **R-ONE `A_2024_00060`(평균매매가격_아파트)** 과 대조한다.
인구를 `verify_population.py` 로 검증한 것과 같은 방식이다.

# 데이터 계약 (DATA CONTRACT) — 팀 공용 SSOT

작성: 2026-07-23 · **최종 개정 2026-08-03** (직전 07-31 A-7 관리자 승인) · 상태: **운영 중 (SSOT)**
**모든 팀원은 이 문서를 따른다. 임의 변경 금지 — 변경이 필요하면 팀장에게 보고할 것.**

---

## 0. 절대 규칙

1. **자기 담당 경로 밖의 파일을 수정하지 않는다.** (병렬 작업 충돌 방지)
2. `data/raw/` 는 원본 보관용 — 가공 결과를 여기 쓰지 않는다.
3. 대시보드가 읽는 파일은 **오직 `data/processed/` 와 `data/geo/`** 뿐이다.
4. 인코딩은 전부 **UTF-8 (BOM 없음)**. JSON은 `ensure_ascii=False`.
5. 좌표는 전부 **WGS84 (EPSG:4326)**, `[경도(lng), 위도(lat)]` 순서(GeoJSON 표준).
6. API 인증키는 코드에 하드코딩 금지 → `.env` 에서 읽는다. `.env` 는 커밋/공유 금지.
7. **API 키가 아직 없다.** 스크립트는 키 없이도 `--sample` 모드로 **형식이 동일한 더미 데이터**를 생성할 수 있어야 한다. 대시보드는 이 더미로 먼저 완성한다.
8. **`_draft` 접미사가 붙은 산출물은 어떤 조인에도 쓰지 않는다.** (A-7 ⑤ 신설)
   초안은 정확도가 검증되지 않은 상태다 — 대표 사례가 `bjd2adm_draft`(적중률 53%)이며 **2026-07-29 경로 자체가 폐기**됐다.
   초안을 조인에 쓰면 틀린 결과가 조용히 전파되고, 나중에 어디서 섞였는지 추적이 안 된다.
9. 🚨 **행정구역을 사람 손으로 바꾸는 것은 관리자 컨펌 사항이다.** (A-7 ⑥ 신설, 2026-07-31)
   대상 — ① `geo_legacy_map.py` 의 `MANUAL_ADM` 신규 등재/수정 ② 경계 버전(`geo_build.py` `DEFAULT_VER`) 변경
   ③ 경계 원천 교체 ④ 코드 변환표의 수기 보정.
   **절차**: 관보·행안부 고시 등 **1차 근거 URL** 을 붙여 관리자에게 보고 → 승인 후 등재하고, 근거 URL을 코드 주석에 남긴다.
   > **왜 컨펌인가**: 이 값들은 검증 장치가 없다. 틀리면 에러가 나는 게 아니라 **특정 지역이 지도에서 사라지거나
   > 인구가 엉뚱한 동에 붙는 형태로 조용히 틀린다.** 대외 상담 자료라 이 오류는 계약 분쟁 근거가 될 수 있다.
   > **관할구역 조정이 동반된 개편은 1:1 이관을 금지한다** — 명칭만 바뀐 게 아니면 인구·경계가 갈라진다.

## 2. 산출물 명세

### 2-0. 모든 산출물 공통 필수 `meta` 〔A-7 ②④ 신설, 2026-07-31〕

`data/processed/` 의 **모든 JSON 은 아래 `meta` 를 반드시 포함한다.** 누락은 계약 위반이다.

```json
"meta": {
  "sample": false,              // 필수. 더미 데이터면 true
  "updated": "2026-07-31",      // 필수. 산출 일자
  "source": "학교알리미 CSV",    // 필수. 원천 이름
  "base_year": 2026,            // 파일 원천일 때 필수 (연 1회 갱신분의 기준연도)
  "source_file": "...csv",      // 파일 원천일 때 필수
  "collected_at": "2026-07-31"  // 재수집 시 값이 변하는 원천(RTMS 등)에 필수
}
```

- **`meta.sample` 로 이름을 통일한다.** `meta.mode: "sample"` 표기는 **폐기** — `poi_*.json` 이 이 형태였다.
  통일 전까지 대시보드는 **양쪽을 모두 검사**한다.
- `sample: true` 인 산출물은 **대외 자료에 사용 금지**다. 화면 경고(B-5)를 만들지 않기로 했으므로
  (2026-07-31 결정) 이 플래그는 **발행 게이트(C-8)에서 전수 검사**로만 통제된다.

### 2-3. `data/processed/population.json` — 인구 (담당: 팀원2)

```json
{
  "meta": {"base_ym": "202606", "source": "행안부 주민등록 인구통계", "updated": "2026-07-23"},
  "data": {
    "11680510": {
      "total": 32145,
      "households": 15230,
      "age": {"0_5": 820, "6_11": 1450, "12_14": 690, "15_17": 640, "18_64": 22000, "65_": 6545},
      "school_age": 2780,
      "trend12": [31900, 31950, 32010, 32145],
      "trend_pct": 0.8
    }
  }
}
```
- `age_year` = `0`~`17` 키의 1세 단위 인구. 사용자 연령 필터는 이 필드만 합산한다.
- ⚠️ **`age_year` 의 나이는 `만 나이`다** (원천이 행안부 주민등록 연령별 인구현황).
  반면 **화면·필터·프리셋은 전부 `한국나이(세는나이)`** 다. 환산은 대시보드가
  꺼내 쓰기 직전에만 한다 — `web/index.html` 의 `toManAge()` (`한국나이 − 2`).
  **JSON 안의 숫자는 손대지 않는다.** 파이프라인·검증(`verify_c8.py`)은 계속 만 나이 축이다.
  - 근거: 전국 합계로 맞대보면 만 6세 인구 294,503 ↔ 초1 재적 294,966 (오차 0.2%),
    만 7세 321,316 ↔ 초2 313,432 (2.5%) 로 `한국나이 = 만나이 + 2` 가 학년과 가장 잘 맞는다.
    (`age_year` 를 연나이로 보면 2019년생 출생아 30.3만 < 인구 32.1만이라 산술적으로 불가능)
- `school_age` = `age_year[3]`~`age_year[16]` 합계 = **만 3~16세**. 화면의 기본 학령인구
  범위(**한국나이 3~16세** = 만 1~14세)와는 다르다. 화면은 이 필드를 쓰지 않고
  `age_year` 를 그때그때 다시 합산한다(`applyAgeRange()`).
- 브랜드 프리셋은 와이키즈 `3~7세`, 와이즈만 `8~16세` — **한국나이**다.
  즉 와이즈만은 **초1~중3**, 와이키즈는 **미취학**이다.
- `trend12` = 최근 12개월 총인구 시계열(오름차순).
- 키는 **행정동코드 8자리**. 시군구·시도 집계는 대시보드가 합산하지 않고 **팀원2가 미리 계산**해 같은 구조로 `data/processed/population_sgg.json`, `population_sido.json` 에 넣는다.

### 2-4. `data/processed/apartment.json` — 아파트 (담당: 팀원3)

```json
{
  "meta": {"period": "202507~202606", "source": "국토부 실거래가",
           "consumption_axis": {"asset_level": "median_price_per_py", "excluded": ["jeonse_ratio"]}},
  "data": {
    "11680510": {
      "deal_count": 142,
      "deal_n_price": 142,
      "avg_price": 185000,
      "median_price_per_py": 7180,
      "avg_price_per_py": 7400,
      "median_price": 172000,
      "low_sample": false,
      "households": 8200,
      "new_ratio": 0.18
    }
  }
}
```
- 금액 단위 **만원**. 평당가는 공급면적 기준(전용률 0.75 가정).
- **`median_price_per_py` 가 자산수준의 정본이다** (2026-08-04). `avg_price_per_py` 는
  비교용으로만 남긴다 — 평균은 초고가 1건에 끌려가고, 전국에서 평균−중앙 차이가
  최대 **1,344만원/평** 벌어진다.
- **`low_sample`** = 24개월 매매 표본 `MIN_DEALS`(10)건 미만. 전국 **178개 동**.
  화면은 이 동의 가격을 **숫자로 띄우지 않고 "표본 부족"** 으로 표시하며,
  코로플레스 채색·5분위 경계에서도 뺀다(`metricVal()`). 값이 없는 게 아니라
  **대표성이 없는** 값이라서다.
- `new_ratio` = 준공 10년 이내 단지 세대 비중.
  ✅ **2026-08-05 교정 완료(C-5).** `metrics*.json` 의 `new_ratio` 는 이제 **세대 기준**이고
  (K-apt `kaptUsedate` + 세대수), 옛 **거래 기준** 값은 `new_ratio_deal` 로 남는다.
  ⚠️ `apartment.json` 안의 `new_ratio` 는 **여전히 거래 기준**이다(RTMS 단독 산출).
  화면·문서는 `metrics` 쪽을 쓴다 — 두 파일의 같은 이름을 섞어 보지 말 것.
- `households` 는 **더 이상 채우지 않는다**(전건 null). 아파트 세대수는 `kapt.json` 이 SSOT 다 → §2-6.
- 🔻 `jeonse_ratio` · `avg_jeonse` 는 **참고값이며 소비력 축에서 제외**한다(2026-08-04, E-2 종결).
  실측 상관 **-0.545**(2,518개 동) — 평당가 상위 5개 동이 0.172~0.363 으로 전부 하위권이다.
  소비력 대용으로 쓰면 **부유한 동네가 낮게** 나온다. 1.0 초과 역전값도 170개 동(최대 2.665).
- 시군구/시도 집계본도 동일 구조로 `apartment_sgg.json`, `apartment_sido.json`.

### 2-5. `data/processed/poi_<sgg_cd>.json` — POI (담당: 팀원4)

```json
{

              "grades":[120,118,121,119,122,120],"grade_classes":[5,5,5,5,5,5]}],
  "academy": [{"name":"OO영어학원","course":"보통교과","lat":37.5,"lng":127.03,"adm_cd":"11680510"}],
  "apartment": [{"name":"OO아파트","lat":37.5,"lng":127.03,"adm_cd":"11680510","households":540,"avg_price":185000,"built":2015}],

  "own":            [{"name":"강동","brand":"와이키즈","lat":37.55,"lng":127.14,"adm_cd":"11740530","addr":"…","first_seen":"202607"}],
  "competitor":     [{"name":"강동암사소마","brand":"소마","lat":37.55,"lng":127.13,"adm_cd":"11740530","addr":"…","first_seen":"202607"}],
  "english_kinder": [{"name":"강동캠퍼스","brand":"폴리어학원","lat":37.54,"lng":127.14,"adm_cd":"11740515","addr":"…","first_seen":"202607"}]

```
- 폐업 건 제외 (영업상태 = 영업/정상 만).
- 좌표 없는 건은 제외하고, 제외 건수를 `meta.dropped` 에 기록.
- `school.type` 은 `초`/`중`/`고`. `grades`·`grade_classes` 는 1학년부터(초 6칸·중고 3칸) 학생수·학급수 〔2026-09-17〕 —
  **특수·순회학급 제외**라 `sum(grades) ≤ students`. 지도 말풍선 전용이며 연령 집계는 `metrics` 가 한다.
- `school.type` 은 `초`/`중`/`고`. 원 밑에 표시하는 학생수도 **`grades` 합**이다 〔2026-09-18〕 —
  `students`(재학생 총원)를 쓰면 말풍선의 학년 합과 **71.9%(8,604/11,968) 학교에서 어긋난다**.
- **학교 좌표 수기 보정** 〔2026-09-18〕 — 학교알리미 CSV 가 **동명이교에 같은 좌표**를 주는 자리가 있다
  (구리 인창중·인창고가 서울 인창중·인창고 좌표에 얹혀 서대문구 충현동에 찍혔다).
  보정표는 `data/manual/school_coord_fix.json`(학교코드 → `lat`/`lng`)이고 `load_school.py` 가 읽는다.
  ⚠️ **행정동은 보정표에 적지 않는다** — 바뀐 좌표로 다시 PIP 한다. 적용 건수는 `school.json`
  `meta.report.<학교급>.coord_fixed` 에 남는다.
- **아파트는 도로명이 없는 단지를 올리지 않는다** 〔2026-09-18 관리자 결정〕 — RTMS 원천의 `road` 가
  빈 값이거나 번호만인 단지는 지오코딩이 **시군구 대표점**에 찍는다(광산구 한 점에 서로 다른 동 33개
  단지가 포개져 있었다). 건수는 `meta.dropped.apartment_no_road`.
  ⚠️ 판정은 **「한글이 있는가」** 다. 도로명에는 숫자가 들어간다(`양일1로`·`이화여대8길`) —
  `[가-힣]+(로|길)` 패턴으로 재면 정상 도로명 4,402건을 유실로 오판한다(실측).
  ⚠️ 이 제외로 **9개 동은 아파트 마커가 0개**가 된다. 단지가 없는 게 아니라 위치를 못 찍는 것이고,
  세대수·가격 집계는 `apartment.json`·`kapt.json` 이라 값은 그대로다.
- **같은 (좌표, 단지명) 아파트는 하나로 병합한다** 〔2026-09-18〕 — 같은 단지가 두 레코드로 갈려
  마커가 겹친다. `deal_count` 는 합하고 `avg_price` 는 **거래건수 가중평균**(단순 평균은 거래가 많은
  쪽을 희석한다). 건수는 `meta.dropped.apartment_merged`.

### 2-6. `data/processed/metrics.json` — 가맹상담 지표 (담당: 팀원3, 최종 조립)

대시보드가 코로플레스를 칠할 때 쓰는 **최종 단일 파일**.

```json
{
  "meta": {"updated": "2026-07-23", "level": "adm"},
  "data": {
    "11680510": {
      "school_age": 2780,
      "academy_cnt": 84,
      "school_cnt": 3,
      "pupils_per_academy": 33.1,
      "avg_price_per_py": 7400,
      "score": 72.5,
      "grade": "A"
    }
  }
}
```
- **`academy_cnt` = 입시·검정 및 보습 학원만** (2026-08-03 관리자 정의).
  NEIS `REALM_SC_NM == '입시.검정 및 보습'` — **전국 77,637개**. 예능(35,644)·국제화(8,742)·
  종합·직업기술·독서실 등 60,752개는 **업태가 달라 제외**한다. 정의 SSOT =
  `scripts/collect_neis.py` 의 `REALM_KEEP`, 근거는 `academy.json` `meta.realm_filter`.
  ⚠️ **이 기준 이전 산출물(전 분야 138,284개)과 증감을 비교하지 말 것.**
  ⚠️ `build_poi.py` 가 같은 상수를 import 한다 — 지도 마커와 지표가 갈라지면 안 된다.
- `pupils_per_academy` = `school_age / academy_cnt` (학원 1개당 학령인구, **높을수록 기회**)

#### 소비력 ②③ 필드 〔2026-08-05 C-5 신설〕

| 필드 | 뜻 | 단위 |
|---|---|---|
| `households` | **주민등록 세대수** (인구 원천) | 세대 |
| `apt_households` | **아파트 세대수** (K-apt) | 세대 |
| `apt_complexes` | 아파트 단지 수 (K-apt) | 개 |
| `apt_ratio` | 아파트 거주 비율 = `apt_households ÷ households` | 소수(0~) |
| `apt_ratio_suspect` | 위 값이 **100% 초과**면 true → 화면이 색·5분위·순위에서 뺀다 | bool |
| `housing_asset` | 주거자산 총액 = `apt_households × avg_price` | **억원** |
| `rental_ratio` / `rental_ratio_max` | 임대단지 세대 비중 **하한 / 상한** | 소수 |
| `built_age` | 세대수 가중 평균 준공 연차 | 년 |
| `new_ratio` | 신축(10년내) 비중 — **세대 기준** (2026-08-05 교정) | 소수 |
| `new_ratio_deal` | 같은 값의 **거래 기준** 구값 (참고·비교용) | 소수 |

- ⚠️ **`households`(주민등록)와 `apt_households`(아파트)는 다른 값이다.** 이름이 겹친 채로
  "아파트 거주 비율"을 계산하면 반드시 잘못 나눈다. 그래서 `apartment.json` 쪽
  `households`(전건 null)를 폴백으로 받던 코드를 2026-08-05 제거했다.
- ⚠️ **아파트 세대수의 SSOT 는 `kapt.json` 이고, `apartment.json` 에 조인해 넣지 않는다.**
  ①`apartment.json` 은 `collect_rtms.py` 가 매달 통째로 다시 써서 조인분이 조용히 null 로
  되돌아간다 ②`apartment.json` 은 24개월 매매가 있는 동만 담아 **아파트는 있는데 거래가 없던
  동 19곳(8,058세대)** 이 빠진다. `build_metrics.py` 의 `load_kapt()` 가 직접 읽는다.
- ⚠️ `housing_asset` 은 `low_sample` 동에서 **결측**이다. 대표성 없는 평균가에 세대수를 곱하면
  오차가 수천억 단위로 증폭된다.
- ⚠️ `rental_ratio` 가 **하한**인 이유: K-apt `codeSaleNm` 의 '혼합'(한 단지에 분양+임대)은
  구성비가 원천에 없다. 임대에 더하면 과대, 버리면 과소라서 **폭으로** 낸다.
- ⚠️ `apt_ratio_suspect` = **경계 원천의 분동 반영 지연**이지 조인 버그가 아니다(전국 67개 동).
  예) 전주 만성지구 — 주민등록은 `혁신동`(2019 분동)인데 경계 폴리곤은 그 땅을 아직
  `여의동`으로 갖고 있어, 아파트 13,296세대가 주민등록 7,053세대인 동에 쌓인다.
  지오코딩 캐시의 `xcheck='mismatch'`(전국 1,300건·1.2%)가 같은 지점을 가리킨다 → **E-4**
- `score` = 0~100 종합 매력도. 산식은 `docs/SCORE.md` 에 문서화(팀원3 작성).
- `grade`: S(85+) / A(70+) / B(55+) / C(40+) / D(그 외)
- 🚫 **`score` · `grade` 는 2026-07-31 폐기됐다.** 위 예시의 두 필드는 **더 이상 산출되지 않는다.**
  `metrics*.json` 은 실측 지표만 담고 `meta.scoring:"retired"` 를 갖는다. 재설계 → `TODO.md` **F-1**
- `metrics_sgg.json`, `metrics_sido.json` 동일 구조로 제공.

### 2-7. `data/processed/competitor.json` — 자사·경쟁사·시너지세권 위치 〔2026-08-03 신설〕

가맹상담에서 **"우리가 어디 있고 경쟁사가 어디 있는가"** 를 보여주는 축.
수집 경로·함정 전문은 [`COMPETITOR.md`](COMPETITOR.md) 가 SSOT.

```json
{
  "meta": {
    "sample": false, "base_ym": "202608",
    "source": {"waikids": "xlsx manual_202607.json (202607)", "soma": "crawl crawl_202608.json (202608)"},
    "counts": {"와이키즈": 54, "와이즈만": 95, "소마": 174, "생각하는황소": 83},
    "by_category": {"own": 149, "competitor": 388, "english_kinder": 107},
    "brand_target": {"소마": ["와이키즈"], "생각하는황소": ["와이즈만"]},
    "own_brands": ["와이키즈", "와이즈만"],
    "geocode": {"ok": 1030, "fail": 0, "rate": 1.0, "imprecise": []},
    "changes": {"new": [], "renamed": [], "moved": [], "closed": []}
  },
  "data": [{
    "id": "soma:대치소마", "brand_key": "soma", "brand": "소마",
    "brand_target": ["와이키즈"], "category": "competitor",
    "name": "대치소마", "addr_raw": "서울 강남구 삼성로 314 (대치동) 보양빌딩 2,3F",
    "lat": 37.5001, "lng": 127.0606,
    "adm_cd": "11680640", "sgg_cd": "11680", "sido_cd": "11",
    "base_ym": "202608", "source": "crawl", "first_seen": "202607"
  }]
}
```

- **`category`** = `own`(자사) / `competitor`(경쟁사) / `english_kinder`(**시너지세권**). 이 3값이 지도 레이어와 1:1 대응한다.
- 📛 **키는 `english_kinder`, 표시명은 `시너지세권`** (2026-08-03 관리자 명명).
  키를 바꾸면 `poi_*.json` 256개·집계 3종·이력이 전부 재생성 대상이고 옛 산출물과 조인이 끊긴다.
  표시명 SSOT 는 `scripts/brands.py` 의 `CATEGORIES` 이며, `meta.category_label` /
  `meta.category_source`(구성 = 영어유치원 폴리·라이즈) / `meta.category_role`(합산 금지 근거) 로 함께 나간다.
- ⚠️ **`english_kinder` 는 경쟁사가 아니다 — `competitor` 와 합산 금지**(2026-08-03 관리자 확인).
  유아 사교육 수요가 모이는 자리라 **자사는 근처 입점이 유리**하다는 참고 신호다.
  합산하면 좋은 자리가 나쁜 자리로 뒤집힌다. 근거는 `meta.category_role` 로도 나간다.
- **`pending`** = 아직 자료가 없는 축(`brands.py` `PENDING`). 현재 *(미정) 와이즈만 시너지세권*.
  **"0개"가 실측인지 미수령인지 구분하는 유일한 근거**라 화면이 이 값을 표시한다.
- **`brand_target` 은 배열이다.** 2026-08-03 와이즈만 축이 들어오면서 타깃이 둘이 됐다
  (와이키즈 경쟁사 5개 / 와이즈만 경쟁사 = 생각하는황소 1개). 한 브랜드가 두 타깃에
  걸릴 수 있다. **단일 문자열로 되돌리지 말 것.**
- **`own_brands`** = `own` 카테고리 브랜드 목록. **자사가 두 브랜드(와이키즈·와이즈만)** 라
  화면이 "자사 = 와이키즈"로 하드코딩돼 있으면 와이즈만이 경쟁사처럼 보인다.
  대시보드의 자사 강조는 이 목록을 따른다.
- **`id` = `<brand_key>:<정규화 지점명>`.** 정규화는 공백·`센터/캠퍼스/지점` 접미만 제거하고
  **괄호 안 글자는 남긴다** — 소마에 `강서마곡소마` 와 `(신)강서마곡소마` 가 실재해서,
  괄호를 지우면 두 지점이 한 id 를 다투며 매달 '이전' 이벤트를 만든다.
- 집계본 3종 — `competitor_adm.json` / `competitor_sgg.json` / `competitor_sido.json`.
  구조: `{code: {own, competitor, english_kinder, total, by_brand}}`. 대시보드가 metrics 에 병합해 지표로 쓴다.
- 이력 — `competitor_history.json` 이 지점별 `first_seen`/`last_seen`/`status` 를 보관한다.
  변동은 **신규 / 개명 / 이전 / 폐점** 4종으로 구분한다(지점명 → 주소 2단 매칭).
- POI 파일(§2-5)에 `own` · `competitor` · `english_kinder` 3개 키가 추가된다.
- **`meta.geocode.imprecise`** 〔2026-09-17〕 = **번호 유실 지오코딩** 지점 목록(`"브랜드/지점명"`).
  원본 주소의 도로명 번호·지번이 좌표를 찾은 후보에 하나도 없으면 좌표가 **다른 건물·동 대표점**이다.
  정상 산출물은 **항상 빈 배열**이어야 하고 `verify_c8.py` 가 이를 FAIL 로 막는다.
  필드 자체가 없으면 이 검사 전에 만든 옛 산출물이다(WARN).

> ⚠️ **경쟁사 수가 줄어드는 방향의 오류가 가장 위험하다.** 지도에서 "경쟁사 없는 좋은 상권"이
> 되고 그 화면이 그대로 상담에 쓰인다. 그래서 `build_competitor.py` 는 ①브랜드별 최소 건수
> ②지오코딩 성공률 95% ③직전 회차 대비 20% 급감 ④metrics 에 없는 행정동 ⑤번호 유실 지오코딩 을 검사해
> 위반 시 `RuntimeError` 로 멈춘다. 크롤이 실패한 브랜드는 **출력에서 빠져 직전 회차 값이 유지**된다.

## 3. 대시보드 명세 (담당: 팀원4)

`web/index.html` 단일 진입점. 정적 파일만, 빌드 툴 없음. Leaflet CDN 대신 **로컬 vendor 파일**로 포함(오프라인 동작).

```
[전국]  sido.geojson + metrics_sido.json → 코로플레스
   │ 시도 클릭
[시도]  sgg.geojson(해당 시도만 필터) + metrics_sgg.json
   │ 시군구 클릭
[시군구] adm_<sgg_cd>.geojson + metrics.json → 동별 코로플레스
   │ 동 클릭
[동 상세]  좌: 지표 패널 / 우: POI 맵(학교·학원·아파트 레이어 토글)
```

- 상단 브레드크럼으로 상위 단계 복귀.
- 지표 패널 4블록: **시장규모 / 경쟁강도 / 구매력 / 접근성** (README 지표 설계표와 동일 순서).
- 용도가 **가맹상담 대면 조회 화면**이므로: 큰 글씨, 고대비, 숫자 강조.
  ⚠️ **고객에게 인쇄물로 건네는 용도는 아니다** (2026-08-05 폐지). 화면을 함께 보며 조회하는 도구다.
  `@media print` 는 실무자가 화면을 뽑아 볼 때를 위해 남겨 두되, **배포용 산출물의 근거가 아니다.**
- 데이터 파일이 없으면 빈 화면 대신 **"데이터 준비중"** 안내를 띄운다.

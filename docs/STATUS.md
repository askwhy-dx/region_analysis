## 🚫 세로 쌓기 폐기 — 마커가 행정동 경계를 벗어났다

관리자가 인천 남동구 논현고잔동 화면에서 **학교 마커 4개가 선택 행정동 경계 밖에 찍힌 것**을 발견했다.

### 원인은 내가 넣은 세로 쌓기였다

측정하니 마커가 실제 좌표에서 아래로 밀려 있었다 (줌 13):

| 학교 | 밀린 거리 |
|---|---|
| 인천사리울초 | **136px ≈ 2.0km** |
| 미추홀외고 | 102px ≈ 1.5km |
| 인천고잔초 · 인천사리울중 | 68px ≈ 1.0km |
| 인천송천초 · 고잔중 · 고잔고 | 34px ≈ 0.5km |

겹침을 풀려고 원과 숫자를 슬롯(34px)만큼 아래로 밀었는데, **밀림이 누적되면 지리적으로 km 단위**가 된다.
낮은 배율에서는 1px 이 15m 이므로 5슬롯이면 2.5km 다. 상담에서 학교 위치를 잘못 짚게 된다.

⚠️ **검사가 이걸 통과시켰다.** 「원·숫자가 서로 겹치지 않음」만 봤기 때문에, 마커가 2km 밀린 상태가
겹침 0 으로 PASS 했다. 검사가 목적(겹치지 않음)만 보고 **전제(마커는 제 좌표에 있어야 한다)** 를 안 봤다.

### 방식 교체 — 옮기지 않고 숨긴다

| | 전 | 후 |
|---|---|---|
| 좌표가 **완전히 같은** POI | 레이어별 원형 흩뿌림(약 8m) — 초·중 조합을 놓쳤다 | **레이어를 가로질러** 슬롯 공유 · 약 39m · **세로(위도) 먼저** |
| 그 밖의 근접 겹침 | 원+숫자를 34px 씩 아래로 쌓기 | **겹치는 숫자만 숨김** (원은 제자리) |
| 숨기는 기준 | — | 다른 숫자와 겹침 **+ 다른 학교의 원에 가림** |

- 흩뿌림 39m 는 **학교 부지 안쪽** 수준이라 상담에서 짚는 위치를 해치지 않는다.
  8m 로는 줌 16 에서 약 5px 여서 18px 원이 그대로 겹쳤다(모담초·모담중 실측).
- 오프셋을 **세로 먼저** 쓰는 이유: 같은 도수에서 경도 간격이 cos(위도)만큼 짧아 가로로 밀면 덜 떨어진다.
- 숨은 숫자는 확대하면 다시 나오고, 말풍선으로는 언제든 볼 수 있다.

### 검증기 교체

- **「학교 마커가 제 좌표에 그려진다」** (`worstShiftPx ≤ 1`) — 이번 결함을 직접 겨눈다
- **「보이는 학교 숫자끼리 겹치지 않음」** — 숨긴 것은 세지 않는다

실측: 논현고잔동 9개 마커 **전부 경계 안** · 밀림 **0px** · 모담초·모담중 원 분리 · 숫자 겹침 0.
검증 데이터 48/0 · 화면 **121/0**. 발행 `fc59150`.

## 마킹 감사 에이전트 신설 — 사람이 발견하는 구조를 끝낸다

관리자 지시: 「이런 오류를 일일이 보고 요청할 수 없으니 LLM 이 검증할 수 있도록 에이전트를 만들어라」.

### 왜 기존 검증으로 안 됐나

이번 회차 결함 두 건은 **검증 2종이 전부 PASS 시킨 채로 발행됐다.**

| 결함 | 통과한 검사 | 왜 통과했나 |
|---|---|---|
| 학교 원 하나 밑에 숫자 둘 | 「숫자끼리 겹침 0」 | 숫자는 실제로 안 겹쳤다. 숫자가 **옆 원 밑**에 붙은 것이었다 |
| 마커가 2km 밀림 | 「원·숫자 겹침 0」 | 겹침은 없었다. 겹치지 않게 **옮겼기** 때문이다 |

검사가 **목적(겹치지 않음)** 만 보고 **전제(마커는 제 좌표에 있다)** 를 안 봤다.
전제를 나열하는 것은 결정적 검사로 되지만, 「상담에서 오해할 화면인가」는 **보는 쪽**이 필요하다.

### 두 층으로 만들었다

**① `scripts/audit_markers.js`** — 화면에서 기하 불변식을 계산한다 (읽기 전용 · 서버 자동 기동)

| 등급 | 규칙 |
|---|---|
| **FAIL** | 마커가 제 좌표에서 밀림(1px 초과) · 학교 숫자끼리 겹침 · 학교 숫자가 다른 학교 원에 가림 · 학교 원 포개짐(줌 15+) · 카드 개수 ≠ 마커 수 · 마커가 지도 영역 밖 · 폴리곤 못 찾음 |
| **WARN** | 마커가 선택 행정동 경계 밖 120m 초과 |
| **INFO** | 경계 밖 60~120m · 낮은 배율에서의 원 포개짐 |

- **표본을 위험순으로 고른다.** 무작위로만 뽑으면 아무 일도 없는 동만 본다 —
  좌표 중복·같은 이름 겹침·학교 밀집을 점수화해 상위 N-2 곳 + 무작위 2곳.
- **위반이 난 지역은 스크린샷 2장**(전체·지도)을 남긴다. 그게 ②의 입력이다.
- **`--selftest`** — 마커를 일부러 60px 밀어 점검기가 잡는지 본다. 이게 없으면
  「위반 없음」이 **점검기가 고장난 것**인지 구분할 수 없다.

**② 에이전트 `marker-audit`** (`.claude/agents/marker-audit.md`)

# 6. 교훈 (반복 방지)

- **계약서가 틀리면 오류가 전원에게 전파된다.** 초안의 "시도 17개"가 그랬다 → 새 팀에도 "계약과 데이터가 다르면 보고하라"를 반드시 지시할 것
- **"못 한 건 못 했다고 보고하라"를 명시하면 실제로 자진신고가 나온다.** 팀원3이 자기 점수 왜곡을 스스로 신고했다
- **작업 순서를 어기면 연쇄 재작업이 터진다.** 팀원2가 코드를 바꾸자 팀원3 산출물이 통째로 낡았다 → 상위 산출물 키 검증 게이트를 각 단계에 넣을 것
- **총인구 보존 하드 가드(불일치 시 RuntimeError)** 는 전 팀 확대 적용 권고 (팀장 평가)
- **동 명칭을 조인 키로 쓰지 말 것.** 표기 차이 358건(`창신제1동`=`창신1동`), 정규화해도 14건 잔존. 반드시 코드로 조인
- **입력이 낡으면 조용히 전파된다.** B-1 때 인구·경계는 신코드인데 `apartment.json` 만 구코드라 metrics 에 orphan 416건이 새어 들어갔다 → **재생성은 항상 입력부터 위로 훑을 것**
- **개칭은 자동 매칭으로 못 잡는다.** 이름이 통째로 바뀌면 좌우에 공통 문자열이 없다. 고시 확인 후 수기 등재만이 답이며, **관할구역 조정이 동반된 경우는 1:1 이관 금지**
- **(2026-07-31) 다운로드는 "성공"이 아니라 "내용"을 검사해야 한다.** RTMS 한 달치가 HTTP 200·정상 크기로
  내려왔지만 본문 92%가 NUL 이었다. 크기·상태코드로는 못 잡고 파서도 죽지 않는다 →
  **원천마다 "이 파일이 말이 되는가" 검사를 붙일 것**(NUL·헤더 존재·행수 하한)
- **(2026-07-31) 결측을 채우면 결측용 폴백이 오작동한다.** POI 에 `adm_cd` 를 전부 채우자,
  "매칭 실패 시 시군구 전체 표시" 폴백이 **정말 0개인 동**에서 발동해 과대 표시가 됐다(B-8) →
  **폴백 조건은 "값이 0" 이 아니라 "필드가 없음" 으로 쓸 것**
- **(2026-07-31) 통계 오류를 고쳐도 해석 문제는 남는다.** 모집단 n=4 를 전국으로 바꿔도
  "학원 적은 곳이 높다"는 순위 구도는 그대로였다. **모집단 문제와 산식 정의 문제는 별개**이며,

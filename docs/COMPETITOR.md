## 3. 함정 (전부 실제로 겪은 것)

### ① 조용한 실패 — 이 축에서 가장 위험하다

사이트가 개편되면 크롤러는 **예외를 던지지 않고 0건을 반환한다.**
그 결과는 지도에서 **"경쟁사 없는 좋은 상권"** 이 되고, 그 화면이 그대로 상담에 쓰인다.
빠지는 방향의 오류라 **눈으로는 절대 안 보인다.**

→ 방어 3중:
1. `brands.py` 의 **`min_expect`**(직전 실측의 약 70%) 미달이면 그 브랜드를 **통째로 버린다**.
   버린 브랜드는 출력에 안 들어가므로 `build_competitor.py` 가 **직전 회차 값을 계속 쓴다**(사라지지 않는다).
2. 실패 시 원문 HTML 을 `data/raw/competitor/_snapshot/<key>_<ym>_fail.html` 로 남긴다.
3. `build_competitor.py` 가 직전 `competitor.json` 대비 **20% 이상 급감**을 `RuntimeError` 로 막는다.

> 실제로 작동했다 — 라이즈 첫 구현이 **6건**을 반환했고(페이지네이션 누락), 가드가 잡아냈다.
> 가드가 없었으면 39 → 6 으로 줄어든 채 조용히 발행됐을 것이다.

### ② 라이즈는 페이지네이션이다 (페이지당 6건)

`/find/find__list` 1페이지만 읽으면 **6건**으로 끝난다. 전체는 9페이지 39건.
`?page=N` 으로 새 항목이 안 나올 때까지 넘겨야 한다. **목록에 주소가 없어** 상세페이지도 필요하다.

### ③ 같은 건물에 별개 지점이 실재한다 — 주소만으로 중복 판정 금지

```
소마 김포한강 1관(211호) / 2관(301호)          ← 별개 지점
폴리 김포캔비GRAD(2층 205호) / 김포(601호)      ← 별개 지점
소마 서판교소마(2층) / 서판교소마센터(2F)        ← 진짜 중복
```
중복 키는 **도로명+건물번호 + 정규화된 층·호**다(`addr_norm.dedupe_key`).
`2층` 과 `2F` 는 같게, `211호` 와 `301호` 는 다르게 본다.
층·호가 양쪽 다 없으면 구분할 근거가 없어 병합되는데, 그건 수용한다.

### ④ 개명을 폐점+신규로 잡으면 안 된다

2026-08 크롤에서 실제로 나왔다:
```
소마 광명소하소마 → 광명하안소마   (주소 동일)
소마 소마성북학원  → 성북소마       (주소 동일)
```
지점명 id 만으로 추적하면 **폐점 1 + 신규 1** 로 이중 계상된다.
→ **①id(지점명) → ②주소** 2단 매칭. 반대로 이름이 같고 주소만 바뀌면 **'이전'** 이다
(청주테크노폴리스소마: 상당구 → 흥덕구).

### ⑤ 괄호를 지우면 두 지점이 한 id 를 다툰다

소마에 `강서마곡소마` 와 `(신)강서마곡소마` 가 **둘 다 실재**한다.
id 정규화에서 괄호 안 글자까지 지우면 두 지점이 같은 id 가 되어
**매달 서로의 주소를 뺏는 '이전' 이벤트가 무한 반복**된다. 괄호 기호만 없애고 글자는 남긴다.

### ⑥ 주소 표기가 원천마다 다르다 → 후보를 여러 개 만든다

```
서울 강동구 양재대로 1636, 7층 와이키즈 강동      쉼표 뒤 층 + 상호명
강원 강릉시 솔올로 93 정도빌딩 4층 강릉교동소마     건물명 + 층 + 상호명
서울 강서구 마곡동 739-1 마곡더블유타워 5층        지번 주소
서울특별시 양천구 신정동 신목로 59, 2층            법정동 + 도로명 혼재
```
`addr_norm.candidates()` 가 "덜 깎은 것 → 더 깎은 것" 순으로 후보를 만들고
`build_competitor.py` 가 순서대로 시도한다. 실측 644건 중 **635건이 원본 그대로 통과**,
9건이 정제 후 통과, 실패 0건.

### ⑦ 원본에 시군구가 없는 주소가 있다

필즈 인천/송도센터가 `인천광역시 신송로 164`(시군구 없음)로 내려온다. 지오코딩이 실패한다.
**크롤 원천이라 우리가 고칠 수 없어** `addr_norm.MANUAL_FIX_PREFIX` 에 **도로명 단위**로 등재했다.
정확 매칭으로 두면 건물번호가 바뀌는 순간(크롤은 매월 새로 받는다) 다시 실패한다.

> ⚠️ **세종시는 시군구가 없는 게 정상이다**(단층제). `missing_sgg()` 가 세종을 예외 처리하지
> 않으면 세종 지점 전부가 오탐으로 뜬다.

### ⑧ 필즈 테이블에서 "시도명으로 시작하는 칸"을 주소로 고르면 안 된다

센터명이 `대구/수성센터` 라서 **이름 칸이 먼저 걸린다.** 실제로 13건이 주소 없이 샜다.
주소는 **도로명·지번 숫자가 있는 칸**으로 판정한다.

### ⑨ 지도에서 경쟁사 마커가 학원 마커에 묻힌다

동당 학원이 수백 개다(다산1동 556개). 경쟁사 2개는 그냥 두면 **통째로 안 보인다.**
`raiseKeyLayers()` 로 시너지세권 → 경쟁사 → 자사 순서로 맨 위에 올린다.
**레이어를 껐다 켜면 순서가 풀리므로 토글 핸들러에서도 다시 부른다.**

### ⑩ 경쟁사 0인 지역은 집계 파일에 키가 없다

`competitor_adm.json` 은 **경쟁사가 있는 행정동만** 담는다(278/3,561).
대시보드가 `undefined` 로 두면 코로플레스에서 **결측(회색)** 이 되어
"경쟁사 없음"이 "데이터 없음"으로 읽힌다. `mergeCompetitor()` 가 **0으로 채운다**.
(B-8 "0은 결측이 아니라 실측"과 같은 취지)

### ⑪ 황소는 **마지막 페이지를 넘어가도 끝났다는 신호가 없다**

`?page=10` 이상을 요청하면 404 도 빈 목록도 아니고 **9페이지(마지막 3건)를 계속 돌려준다.**
라이즈처럼 `found == 0` 으로 끊으면 40페이지까지 헛돌며 같은 3건을 반복해서 받는다.
→ **"새 지점이 안 나오면" 멈춘다**(`seen` 집합 기준). 실측 83건 / 9페이지.

### ⑫ 출력 파일명이 겹치면 앞 자료가 통째로 사라진다

자사 xlsx 가 둘(와이키즈·와이즈만), 크롤도 전체/부분 실행이 있다.

> 나머지 브랜드가 원천을 잃고 **지난달 xlsx 로 되돌아가** 이력에 '이전·개명'이 역행한다.

### ⑬ 주소 정제는 **양방향으로** 검증할 것 (2026-08-03에 실제로 깨뜨렸다)

`원당동1030-5` 처럼 지번이 동에 붙은 표기를 벌리려고
`([가-힣]{2,}(?:동|리|가))(\d)` 로 공백을 넣었더니, **멀쩡하던 4건이 깨졌다** —
`당산동5가` · `금호동1가` · `동소문동4가` · `수성동2가` 는 숫자가 **법정동 이름의 일부**다.
→ 숫자 **뒤**까지 보고(`(?![가-힣0-9])`) 지번일 때만 벌린다.
정제 규칙을 손대면 **기존 성공 건수(644/644)가 유지되는지 반드시 다시 볼 것.**

## 4. 월 갱신 절차

```
region_analysis\update_competitor.bat        ← 더블클릭
```

1. 크롤 6개 브랜드 → `crawl_<ym>.json`
2. 와이키즈 xlsx 로드 → `manual_<ym>.json`  (xlsx 가 그대로면 결과도 그대로다)
3. 와이즈만 xlsx 로드 → `manual_wiseman_<ym>.json`
   ⚠️ 이 원본에는 `데이터기준` 컬럼이 없다 → **파일 수정월**을 기준월로 쓴다
   (`--base-ym` 으로 덮을 수 있다). 관리자가 파일을 새로 주면 기준월도 따라 올라간다.
4. 지오코딩·집계·이력 → `competitor*.json` 4종
5. POI 재조립 → `poi_<sgg>.json` 256개

**끝나면 반드시 볼 것** — 4단계가 찍는 변동 요약:
```
[build] 변동 — 신규 10 · 개명 2 · 이전 1 · 폐점 1
         ↻ 소마 광명소하소마 → 광명하안소마
         ⇢ 소마 청주테크노폴리스소마: 상당구 → 흥덕구
         + 아담리즈/동광주센터
         − 아담리즈/김포센터
```

**중단되면** — 배치가 사유를 찍는다.
- `[중단] 크롤링이 한 건도…` → 사이트 개편/네트워크. `_snapshot` 의 원문 확인
- `[중단] 하드가드 위반` → 급감 또는 지오코딩 실패율 초과. **원인을 먼저 확인**하고,
  의도한 감소가 맞으면 `python scripts\build_competitor.py --no-guard`
- `번호 유실 지오코딩 N건` → 좌표가 다른 건물에 찍힌 것. `--no-guard` 금지, §3 ⑮ 대로 주소 보정표에 등재

**자사 센터가 바뀌면** 해당 xlsx 를 고치고 배치를 돌린다
(원본은 `data/manual/competitor/` 에 sha256 과 함께 보존된다).

| 와이즈만 | `와이즈만 위치.xlsx` | `와이즈만` | `--preset wiseman` |

### 관리자에게 받는 xlsx 양식

**바탕화면에 같은 파일명으로 덮어써 주면 된다.** 배치가 알아서 읽는다.

| 컬럼 | 필수 | 비고 |
|---|---|---|
| `센터명` | ✅ | `지점명`·`캠퍼스명` 도 인식. 같은 이름이 둘이면 자동으로 `#1`·`#2` 를 붙인다 |
| `주소` | ✅ | `도로명주소` 도 인식. **지번·건물명·층·호가 섞여 있어도 된다** — 정제기가 후보를 만들어 맞춘다 |
| `데이터기준` | 선택 | `YYYYMM`. 없으면 **파일 수정월**을 기준월로 쓴다 |

- 그 밖의 컬럼(`번호`·`지역`·`센터장명` 등)은 **있어도 무시**한다. 지우지 않아도 된다.
- 시트명은 **브랜드명**이어야 한다(`와이키즈`·`와이즈만`). 빈 시트는 건너뛰지만,
  **이름을 못 알아보는 시트가 있으면 배치가 멈춘다** — 조용히 빠지는 것보다 낫기 때문이다.
- 주소가 비었거나 정제 실패한 행은 건수와 함께 `[load] ⚠️` 로 찍힌다. **그 줄을 꼭 볼 것.**

### 자료 대기 중인 축 (`brands.py` 의 `PENDING`)

**와이즈만 시너지세권** — 와이키즈의 폴리·라이즈에 해당하는 축. 자리만 잡아 뒀다.
자료를 받으면 `PENDING` 에서 `BRANDS` 로 옮기면 끝이고, 나머지 스크립트·화면은 손댈 게 없다
(xlsx 로 오면 `load_competitor.py` 의 `PRESETS` 에 한 줄, 사이트로 오면 어댑터 하나).

> 대기 상태를 코드·데이터에 남겨 두는 이유: 지도에 **시너지세권 0개**로 보이는 곳이
> *정말 없는 것*인지 *아직 안 넣은 것*인지 구분할 근거가 없기 때문이다.
> `build_competitor.py` 가 매 회차 `⬜ 대기 중` 을 찍고, `meta.pending` 으로도 나가며,
> 대시보드 ④블록이 **"0개로 보여도 없음이 아니다"** 를 표시한다.

## 6. 알려진 한계

- **크롤은 공식 홈페이지 기준이다.** 사이트에 안 올라온 신규 지점은 잡히지 않는다.
- **폐점 판정은 "이번 회차에 안 보임"** 이다. 사이트가 갱신을 늦게 하면 늦게 잡힌다.
  크롤이 실패한 브랜드는 폐점 판정에서 아예 제외한다(사이트 장애 = 전 지점 폐점 방지).
- **자사는 xlsx 기준**이다(와이키즈 202607 · 와이즈만 202608). 크롤 대상이 아니라
  관리자가 갱신해야 한다. 와이즈만은 공식 센터안내(`askwhy.co.kr/center_info`)가 있지만
  목록이 JS 로딩이라 크롤을 못 붙였다 — **관리자 xlsx 재수령이 현재 유일한 갱신 경로**(A-14).
- 브랜드 규모 비교는 **지점 수**뿐이다. 정원·면적·매출은 공개되지 않는다.
- **와이즈만 경쟁사는 생각하는황소 하나만 본다.** 사고력수학 3사(소마·아담리즈·필즈)는
  관리자가 와이키즈 전용으로 지정했으므로, 와이즈만 상담 화면에서 "경쟁사 1곳"이
  적어 보여도 데이터 누락이 아니라 **정의대로**다.
